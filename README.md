# APT Dependency Graph Visualizer

Практическая работа № 2 по дисциплине «Конфигурационное управление».
Вариант № 1. Реализация на Python 3.11+.

## Описание

Консольная программа получает сведения о пакетах Ubuntu APT, строит
направленный граф прямых и транзитивных зависимостей с помощью BFS
**без рекурсии**, выводит ASCII-дерево и сохраняет описание PlantUML
и изображение SVG. Есть режим работы с небольшими тестовыми графами.

Для чтения зависимостей не используются `apt` и сторонние библиотеки:
данные загружаются из индекса `Packages.gz`, распаковываются модулем
`gzip` и разбираются собственным кодом.

## Структура проекта

- `src/main.py` — запуск приложения и обработка ошибок.
- `src/config.py` — загрузка и проверка TOML-конфигурации.
- `src/apt_repository.py` — парсер индекса пакетов Ubuntu.
- `src/graph.py` — чтение тестовых графов, BFS, обращение рёбер.
- `src/visualization.py` — PlantUML, SVG, ASCII-дерево.
- `tests/` — автоматические тесты.
- `tests/data/` — примеры тестовых графов.
- `run.bat` — запуск приложения в Windows.

## Настройки

В файле `config.toml` задаются шесть параметров:

| Параметр | Назначение |
|---|---|
| `package_name` | Имя анализируемого пакета |
| `repository` | URL `Packages.gz` или путь к тестовому файлу |
| `test_mode` | `true` — читать тестовый файл, `false` — Ubuntu |
| `output_file` | Путь к изображению `.svg` |
| `ascii_tree` | Выводить ASCII-дерево (`true` / `false`) |
| `exclude_substring` | Исключать пакеты с указанной подстрокой |

Пример настройки для Ubuntu:

```toml
package_name = "bash"
repository = "https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz"
test_mode = false
output_file = "graph.svg"
ascii_tree = true
exclude_substring = ""
```

Требуется Python 3.11 или новее (для `tomllib`).

## Запуск

Из корня проекта в PowerShell:

```powershell
.\run.bat
```

Либо напрямую:

```powershell
py -m src.main
```

При успешном запуске программа создаёт файл `.puml` с описанием
PlantUML и одноимённый файл `.svg` с изображением графа. Если включён
`ascii_tree`, в терминал выводится текстовое дерево зависимостей.

### Генерация SVG

Программа поддерживает два способа:

1. Онлайн-сервер PlantUML (по умолчанию, требуется интернет).
2. Локальный `plantuml.jar` через Java. В PowerShell задать путь:

```powershell
$env:PLANTUML_JAR = "C:\Tools\plantuml.jar"
.\run.bat
```

Локальный вариант позволяет не зависеть от доступности сервера.
Файлы JAR, SVG и PUML **не включаются в Git-репозиторий**.

## Тестовый режим

В `config.toml` указать:

```toml
package_name = "A"
repository = "tests/data/simple.txt"
test_mode = true
output_file = "graph.svg"
ascii_tree = true
exclude_substring = ""
```

Пример `tests/data/simple.txt`:

```text
A: B, C
B: D
C: D
D:
```

Каждая строка задаёт пакет и его прямые зависимости. Имена тестовых
пакетов состоят из заглавных латинских букв. Дополнительные примеры:

- `tests/data/cycle.txt` — цикл A → B → C → A.
- `tests/data/filter.txt` — исключение пакета X.

Для обратных зависимостей предусмотрена функция `reverse_repository()`
из `src/graph.py`: она обращает рёбра исходного графа, после чего
к результату можно применить `build_graph()` (тот же BFS).

## Запуск тестов

```powershell
py -m unittest discover -s tests -v
```

Тесты проверяют конфигурацию, парсинг индекса, обход BFS, циклы,
фильтрацию, обратные зависимости и визуализацию. Для тестов SVG сервер
PlantUML имитируется через `unittest.mock`, поэтому интернет не нужен.

## Примеры использования

Для построения графов реальных пакетов меняйте в `config.toml`
`package_name` и `output_file`, затем выполняйте `run.bat`:

| `package_name` | `output_file` |
|---|---|
| `bash` | `bash.svg` |
| `nano` | `nano.svg` |
| `grep` | `grep.svg` |

Это примеры конфигураций, а не утверждение о том, что сравнение с APT
для всех трёх пакетов уже проведено.

## Сравнение со штатными инструментами APT

В Ubuntu 24.04 прямые зависимости можно посмотреть командами:

```bash
apt-cache depends bash
apt-cache depends nano
apt-cache depends grep
```

Для рекурсивного анализа можно отдельно установить `apt-rdepends`.

**Сравнение с выводом штатных средств пока не проведено.** Результаты
необходимо записать после фактического запуска APT (это отдельное
требование этапа 5).

Возможные расхождения: программа анализирует один компонент и одну
архитектуру репозитория (`noble/main/binary-amd64`), трактует альтернативы
как возможные рёбра и не разрешает виртуальные пакеты и версии так,
как это делает полноценный менеджер APT. Поля `Depends` и `Pre-Depends`
учитываются как связи графа, без сохранения различия их типов.

## Этапы разработки

1. TOML-конфигурация, валидация и обработка ошибок.
2. Получение прямых зависимостей из Ubuntu APT.
3. Итеративный BFS, циклы, фильтр и тестовые графы.
4. Анализ обратных зависимостей.
5. PlantUML, SVG и ASCII-дерево.

История реализации этапов и слияния веток сохраняется в GitHub.
